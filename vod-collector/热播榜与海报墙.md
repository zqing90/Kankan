# 影视热播榜数据源 & 海报墙首页

> ⚠️ **本文已过时**：这一版是「多站共现自算热度」方案，现已被豆瓣官方榜单取代。
> 现行方案见 **`热播榜数据源.md`**。本文保留作为备用算法（`src/chart.js`）的说明。

> 实测时间 2026-11-06，结论先行，坑都标出来了。

## 一、结论：没有能直接用的"官方热播榜 API"

市面上能拿到"影视热播排行"的路只有三条，各有各的坑：

| 路线 | 代表 | 实测结果 | 适合做首页吗 |
|---|---|---|---|
| 平台官方榜 | 爱奇艺风云榜、腾讯视频榜、优酷榜、芒果 | 只有网页，无公开 API，反爬强（JS 渲染 + 加密参数） | 能做但维护成本高，随时挂 |
| 第三方评分/热度 | 豆瓣、猫眼、TMDB | 豆瓣 JSON 接口可用但**风控严**（本次连续请求后直接 302 拦）；猫眼 403；TMDB 国内**连不通**（超时） | 数据好看，但不稳定，必须缓存 + 降级 |
| 资源站自身 | 23 个苹果CMS 站 | **稳定**、`h=最近N小时更新` 参数好用、海报直连无防盗链、点进去就能播 | ✅ 推荐做主力 |

关键发现：**资源站 API 的 `order` 排序参数是假的**（`order=vod_hits desc` 返回和默认一模一样），所以拿不到"按播放量排序"。但 `h=168`（最近 168 小时更新）是真实生效的，这是唯一可用的"热度信号"入口。

于是做了一件事：**用"多站共现 + 更新新鲜度"自己算热度**。

## 二、自算热度的算法

```
score = 收录站数 × 10      // 8 个站同时收录 = 80 分，最核心信号
      + 24h 内更新 +8      // 48h 内 +4
      + 连载中 +5          // "更新至第 N 集"，说明还在播
      + 已完结/正片 +3
```

为什么"收录站数"能当热度：资源站是**按市场需求上片**的，一部片被 8 个站同时收录，基本等于"当下有人看"。反过来，冷门老片通常只有 1-2 个站有。

实测效果（168 小时内）：

| 分类 | 条目数 | Top3 |
|---|---|---|
| 剧集 | 40 | 芝加哥烈焰第十五季(9站)、分手代理(9站)、谷雨(9站) |
| 动漫 | 40 | 缔灵爱水心缠(10站)、FX战士久留美(9站)、冰剑的魔术师第二季(8站) |
| 电影 | 20 | 余命一年买男人(8站)、我想留在你身边(8站)… |
| 综艺 | 40 | 自然公开课第二季(6站)… |
| 短剧 | 40 | 与海鸥同行后大海成了我家鱼塘(6站)… |

**要诚实说明**：这是"最新上线 + 多站共现"的合成榜，不是平台播放量榜。好处是**每个条目点开都能播**，坏处是会有不少 B 级片/外语片挤进来（资源站上片就是这个结构）。

## 三、海报墙是怎么做的

```
node src/server.js 8765      # 打开 http://localhost:8765
```

页面能力：

- 顶部分类 tab（电影/剧集/综艺/动漫/短剧），带数量角标
- 海报墙 7 列自适应，2:3 比例，前三名金/银/铜排名角标，≥6 站标"热"
- hover 浮层显示「N 站收录 + 更新进度」
- 点卡片 → 详情弹窗：海报、主演、简介、**实时检索的播放源列表**（带清晰度/时长/加密标记）
- 点播放源 → 独立播放浮层（16:9，hls.js），可返回详情

技术上两个关键点：

1. **海报直接引资源站原图**，不用代理。实测 `p.bfvp26.com` 等图床无防盗链（这点和豆瓣相反，豆瓣图不带 Referer 直接 418）。
2. **`ac=list` 不返回海报**。列表接口只给精简字段，必须用 `ac=detail&pg=1&h=168` 拉，才有 `vod_pic`。这是本次踩的最大一个坑——第一版海报墙 90% 的图是空的。

## 四、性能

| 场景 | 耗时 |
|---|---|
| 冷启动（8 站 × 100 条 + 分类树） | 7.6 s |
| 命中缓存（10 分钟 TTL） | < 1 ms |
| 点击卡片 → 播放源列表就绪 | 8~15 s（要逐条验证 8 条线路能否取流） |

首页只读缓存，所以首屏是毫秒级；榜单在后台按需重建。`/api/chart?force=1` 强制刷新。

## 五、如果一定要接豆瓣榜

豆瓣有两个接口能用，但都要当"易碎品"对待：

```
热门电影/剧集  https://movie.douban.com/j/search_subjects?type=movie&tag=热门&sort=recommend&page_limit=20&page_start=0
分类排行      https://movie.douban.com/j/chart/top_list?type=11&interval_id=100:90&action=&start=0&limit=20
```

三个坑：

1. **风控**：同一 IP 连续请求几次就返回 302（跳验证页）。必须：请求间隔 ≥2s、带 `Referer: https://movie.douban.com/`、带真实 UA、失败降级到缓存。
2. **海报防盗链**：`img*.doubanio.com` 不带 Referer 返回 **418**，前端 `<img>` 直接引会全部裂图。必须自建图片代理（服务端带 Referer 取图 + 本地缓存）。
3. **和播放对不上**：豆瓣条目名和资源站名常有一字之差（`空枪` vs `空枪（粤语）`），要模糊匹配 + 人工兜底。

所以建议：**豆瓣只当"评分/口碑"的补充字段**（有就显示，没有不显示），榜单主体用资源站自算。这样豆瓣挂了首页也不会废。

## 六、部署建议

| 项 | 建议 |
|---|---|
| 刷新频率 | 10~30 分钟一次，别更勤（会被资源站限流） |
| 缓存 | `out/chart.json` + 进程内，容器重启不丢 |
| 站点数量 | 8~10 个主力站足够，站越多增量越小（片源高度重叠） |
| 图片 | 直接引原图，但要加 `loading="lazy"`，否则首屏几十个请求 |
| 兜底 | 榜单接口失败时返回上次缓存，不要给空页面 |

## 八、合规

榜单里的片源来自未授权资源站，海报与简介亦然。做**技术演示、个人首页**没问题；对外商用（尤其带广告/会员）侵权风险很高，建议只保留元数据展示，播放走你自己的授权源。
