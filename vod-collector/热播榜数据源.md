# 热播榜数据源：实测对比与接入方案

> 结论先行：**豆瓣的 rexxar 榜单接口是当前最合适的第三方热播源**——17 个榜单、528 部条目、字段带评分/评分数/集数/卡司/海报，连续 35 次请求零封禁。
> 首页已改为直接读它，不再用资源站共现度自算热度。

## 一、为什么换

上一版用「23 个资源站同时收录 = 热」来倒推热度，问题很明显：

- 资源站按市场需求上片，上片速度和真实观看量不同步，外语 B 级片会大量涌入；
- 热度分是自造指标，没有外部校准，站内「播放量」字段实测是假的（`order=vod_hits desc` 与默认排序完全一致）；
- 换片源站就换榜单，不稳定。

改成直接读**有人持续维护的公开榜单**，榜单本身由豆瓣的编辑/算法更新，我们只做搬运和展示。

## 二、候选源实测（2026-11-06）

| 源 | 结果 | 结论 |

结论：**中文影视榜单里，豆瓣是唯一「字段完整 + 海报可用 + 国内直连稳定」的源**。

## 四、四个必踩的坑

### 1. 榜单混着两套数据结构

这是最容易卡住的地方。剧集、综艺、动画、纪录片是一套字段；**电影榜是购票结构，字段完全不同**：

| | 剧集/综艺/动画/纪录 | 电影 |
|---|---|---|
| 海报 | `pic.normal` / `pic.large` | `cover.url` |
| 副标题 | `card_subtitle` | `info` |
| 导演 | 在 `card_subtitle` 第 4 段 | `directors[]` 数组 |
| 演员 | 在 `card_subtitle` 第 5 段 | `actors[]` 数组 |
| 集数 | `episodes_info` | `release_date`（如 `08.19`） |
| 简介 | `comment` | `description` |

只按 `pic` 取值，结果就是**剧集正常、电影整排破图**——我第一版就是这样，8 张电影海报全是空白格。修复方式见 `src/douban.js` 的 `normalize()`，用 `!it.pic && it.cover` 判断走哪套。

### 2. 海报不带 Referer 一律 418

```
无 Referer          → 418
带 movie.douban.com → 200 · 104KB
```

所以前端 `<img src="豆瓣地址">` 必然全裂。必须由服务端代理：`/api/poster?u=<encoded>`，代理时加 Referer，同时落盘缓存。

同时**按用途选尺寸**：卡片用 `s_ratio`（约 30KB），详情用 `m_ratio`（约 100KB）。一开始我把两者都统一成 `m_ratio`，528 张卡片图直接翻三倍流量。

### 3. 老接口已死，别在 `/j/search_subjects` 上浪费时间

之前测豆瓣"风控严格"是因为打的是老接口。换到 rexxar 后完全不是一个量级：

| 测试 | 结果 |
|---|---|
| 连续 15 次无间隔 | 15/15 全 200 |
| 0.15s 间隔 20 次 | 20/20 全 200 |
| 12 次 0.6s 间隔 | 12/12 全 200 |

**关键是 UA 和 Referer 要对**，模拟豆瓣自己的 App 请求。即便如此，仍按「30 分钟缓存 + 磁盘兜底」设计，不做每次实时打。

### 4. 豆瓣片名和资源站片名对不上，会播错片

「搜《生日快乐》（埃及电影）→ 播出一部 1080×1920 的竖屏短剧」——这是真实发生过的。资源站里同名短剧、解说版、预告片极多，直接取第一条必然翻车。

修复方式是给候选打分（`pickBest()`）：

```
片名完全一致        +100
片名前缀匹配        +40
命中"解说/预告/花絮/速看/混剪"  -200
年份一致            +30
每条可播线路        +2
```

改完之后同一部片命中的是 1h49m 的横屏正片，不再是 90 分钟的竖屏短剧。

## 五、降级策略

```
请求成功 → 写 out/douban.json，标记 cached:false
30 分钟内 → 直接读缓存（7ms）
超过 30 分钟 → 重新抓；抓取失败且有旧缓存 → 返回旧数据 + stale:true
首页收到 stale → 顶栏显示「⚠ 源站暂时不可用，显示 xx 时间的数据」
```

也就是说豆瓣临时抽风时，首页不会白屏，只会提示数据时间。

## 六、如果豆瓣这条路哪天也断了

按优先级降级：

1. **猫眼 `m.maoyan.com/ajax/movieOnInfoList`**（已验证 200）——只覆盖电影，可作电影榜替补；
2. **云合 / 骨朵 / Vlinkage** 网页解析——专业剧集热度，字段需自己啃 HTML；
3. **B站排行 + 微博热搜**——泛娱乐热度，适合做「侧栏热点」而不是主榜；
4. **退回上一版的自算热度**（`src/chart.js`）——质量差但永不缺源。

`src/chart.js` 保留着，走 `/api/chart`，作为最后兜底。

## 七、合规与边界

- 榜单条目、评分、简介来自豆瓣公开页面，个人做聚合展示问题不大，但**商用需自行评估**；海报版权归片方，做公开站点建议只存缩略图。
- 播放能力是另外接的（点开详情时按片名去资源站检索），与榜单源解耦。榜单换源不影响播放链路。
